# 云端状态锚定跨会话接力（Cloud-Anchored Handoff）规范

## 1. 核心理念：终局交付优先，天然继承上下文

在 SharePoint 云端镜像工作区（`[SHAREPOINT REMOTE WORKSPACE]`）加持下，绝大多数调查、代码审查、问题诊断与常规重构任务均可直接在本会话内完成并输出 `FINAL_ANSWER`：
- **优先当轮结题**：若核心分析、审查结论或代码修改已完成，直接输出完整的 `FINAL_ANSWER` 交付报告，在当前会话圆满收官。
- **跨会话接力触发条件**：当执行超大型多阶段工程且推进至第 25 至第 29 轮仍有未完成的 `plan.md` 实施步骤时，输出标准 `handoff` 块移交进度。
- **天然继承与零重复确认**：后继会话开局将天然继承最新的 `[SHAREPOINT REMOTE WORKSPACE]` 全量文件 URL 映射表与 `plan.md` 物理清单，直接从 `P0` 第一顺位动作切入执行，无需重新向用户确认初始目标。

## 2. 交接内容准则：高密度结论沉淀与云端状态对齐

1. **沉淀已验证分析结论与审阅证据**：
   - 高密度记录本会话已确认的模块分析结论、已核实的缺陷证据链（文件路径 + 精确行号 + 根因 + 修复方案）以及关键接口契约。后继智能体直接继承这些已验证结论，仅对剩余模块进行云端直读补充。
2. **物理任务计划对账（`plan.md` Alignment）**：
   - 明确记录 `plan.md` 中已完成项（`- [x]`）与剩余待办项（`- [ ]`），以及已落盘的阶段性报告路径（如 `.cph/reports/...`）。
3. **云端工作区同步状态对齐**：
   - 在已变更文件清单中清晰标注同步状态：`[CLOUD-READY]`（已热同步至 SharePoint 云端，后继会话可直接云端检索）、`[LOCAL-NEW: use read_file]`（新建本地文件，后继会话按需使用 `read_file` 读取）或 `[PENDING]`（同步排队中，后继会话按需使用 `read_file` 读取）。
4. **`P0 / P1` 双层行动指南与反早退收敛**：
   - **`P0（断点现场恢复 / Immediate Resumption）`**：给出后继会话第 1 轮即可直接执行的具体动作（如立即对剩余模块执行 `patch_file`、运行指定测试命令或合稿输出最终报告）。
   - **`P1（战役核心推进 / Core Campaign Progression）`**：对照 `plan.md` 逐项完成剩余 `- [ ]` 任务。
   - **反早退收敛准则**：后继会话完成 `P0` 断点恢复后，继续推进 `P1` 直至 `plan.md` 全部待办事项均达成 `- [x]` 并验证绿灯，随后输出 `FINAL_ANSWER` 完成全局交付。

## 3. 标准 `handoff` 输出格式

当需要触发跨会话接力时，单独输出以下 ````handoff` 代码块：

```markdown:handoff
# 跨会话工程接力锚点 (Cloud-Anchored Handoff)

## 1. 任务目标与物理任务计划对账 (`plan.md`)
- **核心交付目标**: 简述用户的核心需求与最终验收标准。
- **`plan.md` 完成进度**: 列出已完成的 `- [x]` 项与剩余 `- [ ]` 项。

## 2. 已沉淀的技术审计结论与核心证据链
- 记录已确认的关键接口签名、核心数据流、已核实的缺陷位置（文件路径 + 行号范围 + 根因结论）。

## 3. 已修改/生成文件清单与云端同步状态
- 列出变更文件路径、對應 SharePoint URL 及状态标签（`[CLOUD-READY]` / `[LOCAL-NEW: use read_file]` / `[PENDING]`）。

## 4. 后继会话 `P0 / P1` 行动指南
- **P0（断点现场恢复 / Immediate Resumption）**: 明确指出后继会话第 1 轮应立即执行的具体操作、目标文件与命令。
- **P1（战役核心推进 / Core Campaign Progression）**: 列出完成剩余 `plan.md` 待办项后的集成验证命令与 `FINAL_ANSWER` 汇总交付要求。
```
