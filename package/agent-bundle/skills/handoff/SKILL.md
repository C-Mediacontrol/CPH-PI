# Handoff — 跨会话自主任务交接与审计技能

本技能负责在会话即将结束、达到轮数上限（第 29 轮）、或会话突发异常（如 429 频控/连接中断）时，执行专业级审计与交接提炼，与工作区 `plan.md` 物理任务清单对账，输出标准高保真交接文档，确保后继接力智能体（Successor Agent）能够零磨损无缝接管任务。

> **智能体挂载与双模态契约**：
> - **主控智能体 (Main Agent)** 挂载：执行**宏观工程交接 (Macro Handoff)**，提炼全局架构演进状态、与工作区 `plan.md` 对账物理任务清单勾选状态、输出 P0/P1 两级待办；
> - **子智能体 (Coder / Researcher)** 挂载：执行**微观局部交接 (Micro Sub-Handoff)**，提炼单项任务代码补丁断点、失败单测用例或未完调研线索，供后继接力智能体接续攻坚。

---

## 核心职责

当你被激活或收到交接指令时，表明当前长耗时任务正处于跨会话接力期。你的核心任务是：
1. 梳理前序会话执行历程与真实技术推演；
2. 检索并与工作区 `plan.md` 物理任务清单严格对账；
3. 提炼出结构严谨、主客观分离、包含深度技术见解与 P0/P1 分级待办的 Markdown 交接文档；
4. **直接输出 ```handoff ... ``` 代码块**承载完整高保真 Markdown 交接文档，系统调度核将自动识别并原子落盘归档，接力智能体自动无缝接管；
5. 汇报关键交接要点与首要攻坚待办，恪守反早退铁律；
6. **接力智能体防失忆契约与全景快照对齐 (Anti-Amnesia Contract & Incremental Snapshot Alignment)**：
   - **防失忆认知**：接力智能体处于既定战役的攻坚推进期，天然继承工作区已有的 `plan.md` 物理清单与全景快照视野，直接依据 P0/P1 待办推进单点补缺或对账收敛，无需重新向用户确认初始工程目标；
   - **全景快照无缝对齐**：接力启动时由系统全自动投递递增版本快照（`workspace-vN.txt`），确保交接文档与云端最新代码事实最终一致。

## 交接文档核心规范 (High-Fidelity Specification)

高质量的交接文档注重主客观信息分离与深度技术沉淀，避免机械流水账，根据你的身份自适应侧重不同维度：

### 1. 【任务目标与背景 (Task Goal & Context)】
- **Main 宏观视角**：完整记录用户最初下达的核心目标、业务要求与总体规划拓扑；
- **Subagent 微观视角**：记录主控派发该子任务的局部目标、限定文件范围与验收标准。

### 2. 【阶段性架构见解与工程设计推演 (Mental Model & Architectural Decisions)】
- **AI 架构思考与核心研判**：提取前序会话中对系统源码、模块耦合、技术债务与业务逻辑的**实质性专业见解与重构方向**。明确记录核心技术决策与设计取舍；
- **正式交付物与成果引用**：主动检索工作区是否存在正式的设计文档、实施计划或分析报告（如 `.docs/specs/`、`.docs/plans/` 或 `.docs/reports/`），将其关键结论与文件路径作为核心锚点引用。

### 3. 【已验证物理基线与客观事实 (Verified Baseline & Facts)】
- **物理基线状态**：明确当前 Git 分支与 HEAD 状态、依赖环境与关键验证结果（如单元测试通过/失败情况）；
- **物理账本引用 (Pass-by-Reference)**：系统底层已自动维护无损物理预写账本（`.cph/state/execution-ledger.md`）。交接文档无需冗长抄录全部机械流水，只需提炼关键里程碑结论，并指引接力者按需调阅物理账本。

### 4. 【物理任务计划对账 (Physical Plan Alignment)】
交接必须与工作区 `plan.md` 的当前勾选状态对账，明确战役推进真实进度：
- **已完成项对账 (`- [x]`)**：清晰罗列已经达成并打勾的计划项及对应的验证证据；
- **待攻坚项对账 (`- [ ]`)**：清晰罗列尚未执行或正在执行的切片任务；
- **阻断项标注 (`[!]`)**：若存在外部依赖或不可行项，标注阻断原因。

### 5. 【已探明的反模式与暗坑警示 (Anti-Patterns & Caveats)】
- 明确列出代码库中已识别的代码坏味道、设计缺陷（如超过 1,000 行大文件、散落条件分支、缺失超时重试、竞态条件等）；
- 记录前序已探明的无效路径与试错经验，供接力者参考。

### 6. 【关键卡点、报错与最新诊断 (Current Blockers & Diagnostics)】
- 若包含【事故黑匣子快照】或末期失败调用，重点提取最后 2 轮的原始报错信息（如编译错误、网络 429 频控、文件找不到等）；
- 结合模型的思考研判，给出清晰的断点根因分析（Root Cause Analysis），指出前序尝试为什么会受阻；
- **Coder 视角**：明确列出当前哪个具体单元测试未跑通、报错堆栈是什么。

### 7. 【已变更/生成文件清单 (Modified & Created Artifacts)】
- 聚合列出前序会话中通过 `write_file`、`patch_file` 创建或修改过的全部核心文件相对路径；
- 说明每个变更文件的当前状态（例如已完成、部分打补丁、待编译验证等）。

### 8. 【接力待办事项与反早退铁律 (Actionable Next Steps & Anti-Early Exit Invariant)】

向接力智能体（Successor Agent）下达清晰、具体的首要攻坚指令。待办事项强制两级分化：

- **`P0 (断点现场恢复 / Immediate Resumption)`**：
  - 优先级最高，接力第一步必须立即恢复当前断点现场、未跑通单测或未完调研；
  - 给出上下文封闭的明确首步指令（如“直接打开 X 文件的 Y 行修复报错”、“接续运行测试命令 `bun test tests/xxx.test.ts` 恢复绿灯”）。
- **`P1 (战役核心推进 / Core Campaign Progression)`**：
  - 按工作区 `plan.md` 中未勾选的 `- [ ]` 业务切片继续攻坚；
  - 给出后续按序攻坚的垂直切片清单，指引接力者调派子代理或按序施工。

> **★ 反早退铁律 (Anti-Early Exit Invariant) ★**：
> **必须防范早退行为：绝不允许将 P0 跑完等同于全局交付或提前输出 FINAL_ANSWER！** 只要工作区 `plan.md` 物理清单中仍有未完成的 `- [ ]` 业务切片，接力会话必须继续执行。接力智能体在完成 P0 断点现场恢复后，必须无缝进入 P1 战役核心推进，直到 `plan.md` 物理任务清单全量打勾清空且全量测试通过，方可收敛交付。

## 执行流程

1. **解析输入上下文与对账**：
   - 提取前序会话中 AI 的真实架构思考、未决卡点与核心验证结论；
   - 检索工作区 `plan.md` 物理任务清单并核实勾选状态；
   - 检索工作区正式交付物与物理账本指针（`.cph/state/execution-ledger.md`）；
2. **输出原生交接代码块**：
   - 直接输出 ```handoff ... ``` 代码块，将 8 大维度规范的完整 Markdown 内容包裹其中；
   - 系统调度核将自动提取该代码块并持久化归档，后继接力智能体将以此为基线无缝接续；
3. **输出交接完成摘要**：
   - 在代码块后简要说明交接完成状态与接力 P0/P1 首要任务，并重申反早退要求。
